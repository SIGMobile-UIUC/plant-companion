# Plant Companion production BLE v1

Owning implementations: `firmware/PlantCompanion/pc_core.h`, `PlantCompanion.ino`, and `app/lib/ble/`. Shared vectors: `protocol/golden-v1.json`, generated by the executable production-core test, consumed by Dart tests. The diagnostic sketch uses a different service and is not supported by this client.

## GATT and framing

| Role | UUID | Properties / length |
| --- | --- | --- |
| Service | `d1a10000-7c2f-4a9d-a6b4-36b51743c301` | Production only |
| Info | `d1a10001-7c2f-4a9d-a6b4-36b51743c301` | Read, 20 bytes |
| Control | `d1a10002-7c2f-4a9d-a6b4-36b51743c301` | Write with response, 20 bytes |
| Data | `d1a10003-7c2f-4a9d-a6b4-36b51743c301` | Notify, 20 bytes |

All integers are little endian. Every frame fits the default 20-byte ATT application payload; no MTU negotiation is needed. Six data notifications carry one 48-byte record. Transfer batches contain at most eight records. Firmware paces notifications at 20 ms; the client has a 12-second command timeout. One foreground connection and one command/transfer at a time are sufficient.

Subscribe to Data **before** sending HELLO. The board waits for the notification subscription; HELLO's matching END proves the notification path. Discovery filters the production service, reads Info, and validates version/features/identity. Advertisement names and Android addresses/iOS peripheral identifiers are display/connect hints, never ownership keys. The immutable app identity is `ble:` plus the six Info identity bytes as twelve lowercase hex digits.

## Info (20 bytes)

| Offset | Field |
| --- | --- |
| 0 | Version = 1 |
| 1 | Features: history=1, fresh=2, clock=4, calibrated=8, storage error=16 |
| 2–7 | Stable eFuse-derived device identity (six bytes, transmitted order) |
| 8 | uint32 stream identity, NVS-persisted, nonzero |
| 12 | uint32 oldest retained sequence; zero when empty |
| 16 | uint32 newest committed sequence; zero when empty |

A factory-erased device creates a new stream. The phone preserves older generations while resetting that stream's cursor. A sequence moving backwards within the same stream is an error, never silently accepted.

## Control (20 bytes)

`version:u8 @0, operation:u8 @1, token:u64 @2, arg0:u32 @10, arg1:u32 @14, CRC16:u16 @18`. CRC16-CCITT, polynomial 0x1021, initial 0xffff, covers bytes 0–17. Dart uses BigInt for full 64-bit identities.

| Operation | Value | Arguments / reply |
| --- | --- | --- |
| HELLO | 0 | Empty matching END; notification readiness proof |
| HISTORY | 1 | arg0 = last contiguous committed cursor, arg1 = limit ≤8; records strictly after cursor, then END |
| LATEST | 2 | Latest non-anchor measurement, then END; importing it does not advance the history cursor |
| FRESH | 3 | Nonzero durable request token; persist a new manual sample, return that exact sample, then END |
| TIME | 4 | arg0 = phone UTC seconds, accepted 2020–2100; return persisted current-boot anchor |
| ACK | 5 | arg0 = committed cursor; advisory, no reply and no history deletion |

New manual tokens are rate-limited to one per five seconds. Retrying a retained FRESH token returns its original persisted manual sample. Flutter persists the pending token before sending it and clears it only after the matching kind/token record is saved. Manual acquisitions never reset the next scheduled deadline. Repeated taps also share the app's existing per-plant busy guard.

TIME writes at most one anchor per boot; subsequent requests replay it, preserving ring capacity. The UTC/uptime offset is not restored blindly after a reboot. Phone clock accuracy is the clock source, not an RTC guarantee.

## Persisted record (48 bytes)

| Offset | Field / unit |
| --- | --- |
| 0 | Version = 1 |
| 1 | Kind: startup=1, scheduled=2, manual=3, clock anchor=4 |
| 2 | Validity bits: soil=1, temperature=2, humidity=4, light=8 |
| 3 | Flags: soil calibrated=1, sustained ADC rail=2 |
| 4 / 8 / 12 / 16 | uint32 sequence / boot identity / uptime seconds / UTC seconds (0 = unknown) |
| 20 | uint64 originating request token (0 for unsolicited/serial samples) |
| 28 | uint16 soil centipercent (0–10000); unavailable=0xffff |
| 30 | int16 temperature centi°C (−4000–12500); unavailable=−32768 |
| 32 | uint16 humidity centipercent (0–10000); unavailable=0xffff |
| 34 | uint16 ADC-side soil millivolts, diagnostic only |
| 36 | uint32 millilux; unavailable=0xffffffff |
| 40 | Reserved uint32 = 0 |
| 44 | IEEE CRC32 over bytes 0–43 (reflected 0xedb88320, initial/final xor 0xffffffff) |

An anchor has no valid sensor values and a nonzero UTC. Invalid metrics use the exact sentinels; zero humidity, soil percent or lux can be valid. Flutter maps invalid metrics to null, converts temperature through the app's existing unit helper, and does not estimate soil percent.

## Data notifications (20 bytes)

| Type | Layout |
| --- | --- |
| DATA = 1 | version@0, type@1, fragment index 0–5@2, count=6@3, low uint32 of token@4, sequence:u32@8, eight payload bytes@12 |
| END = 2 | version@0, type@1, full token:u64@2, record count:u8@10, flags:u8@11 (gap=1, more=2), last sent sequence:u32@12 (requested cursor if empty), snapshot newest:u32@16 |
| ERROR = 3 | version@0, type@1, full token:u64@2, code:u8@10, detail:u32@12, remaining bytes zero |

Error codes: malformed=1, busy=2 (detail = retry delay ms when rate-limited), storage=3, incompatible=4, not found=5. Malformed/wrong-token/truncated/conflicting fragments do not advance a cursor. Identical duplicate chunks are harmless. A matching END must describe a complete CRC-valid batch. HISTORY additionally validates increasing sequences and explains skipped positions with the gap flag.

## Durability, attribution and time

Firmware retains 1024 slots ×48 bytes plus a 16-byte file header (49,168 bytes). At 72 scheduled samples/day, seven days uses 504 slots, leaving 520 for startups, anchors and manual samples. FIFO eviction is capacity based: exceptionally frequent manual sampling or power cycling can shorten the time horizon. Missing/overwritten sequences are reported as gaps. ACK does not erase the ring. LittleFS preallocates one file, writes a CRC-protected slot, flushes and reads it back before publication; boot recovery scans valid slots without relying on a separate head pointer. Power loss can discard a torn slot; a CRC-valid write with an uncertain flush outcome is recovered. The first unformatted filesystem can initialize once; later mount/header failures are surfaced and never automatically erased. NVS stores identity, boot counter and CRC-protected calibration, not a head update per sample.

SQLite schema v3 adds physical identity/hints, BLE records and sync state without rebuilding legacy tables. One transaction inserts/verifies a complete batch and advances its cursor; ACK follows commit. An ACK loss reuses SQLite's cursor. A SQLite failure leaves the cursor/pending token unchanged. Uniqueness is `(device ID, stream ID, sequence)`, and conflicting bytes at an existing identity are rejected. Latest reads order by stream generation and device sequence, so importing older history cannot replace the latest measurement. Known measurement times retain seven days relative to the latest packet; unknown-time rows are bounded to the device's 1024-sequence horizon. Clock anchors remain available for retained boot records.

Clock anchors can estimate earlier records from the **same boot** using uptime differences (`phone_anchored`). Device-timestamped later samples are `device_anchored`. Older unanchored boots stay `unknown`; UI hides their fabricated epoch sentinel and says measurement time unknown. Import time is never presented as measurement time.

Ownership changes invalidate stale captures. A previously used device receives a sequence floor at reassignment; unseen pre-assignment samples are stored without a plant owner, and a fresh sample is requested for the new plant. Durable sync state survives device deletion to prevent cursor replay from resurrecting old ownership. Simulator reads/writes/scheduling reject physical devices, and current UI readings are filtered by the assigned source.

The board records while the phone is absent. The phone reconnects on launch/resume, imports latest promptly and catches up in bounded batches. A 30-second foreground poll checks device-side progress; it is not the 20-minute sampling clock. Pausing closes the link; no new native background service is introduced. Web/desktop retain simulator use and explain that physical BLE requires the mobile app.
